# Запуск и доступ для других игроков

Как поднять сервер и дать друзьям зайти в комнату — в локальной сети и через
интернет. Сама игра authoritative-серверная: всё состояние комнаты живёт в
запущенном `node`-процессе, поэтому **сервер должен работать всё время, пока
идёт игра** (остановили — комната пропала).

> Кроме запуска с домашней машины игру можно развернуть на своём VPS постоянно —
> за nginx, под подпутём вида `/code-names/` и с автозапуском (раздел 5). Тогда
> туннели из разделов 3–4 не нужны.

## Быстрый старт: одна команда

Если нужно просто позвать друзей и играть — хватит одной команды. Она поднимает
сервер, поднимает туннель и печатает готовую ссылку:

```powershell
npm run play
# сразу с кодом комнаты:
npm run play -- -Room ABCD
# без установки cloudflared, через localhost.run:
npm run play:lhr
# другой порт:
npm run play -- -Port 3100
```

Окно не закрывать, пока идёт игра; `Ctrl+C` — остановить сервер и туннель разом.
Если окно всё же закрыли крестиком и процессы остались в фоне:

```powershell
npm run tunnel:stop
```

Особенности:

- Перед туннелем скрипт **проверяет сервер настоящим запросом** к
  `http://localhost:<порт>/` — занятый порт ещё не значит рабочий сайт. Не
  ответил за 20 секунд — запуск прерывается с показом лога сервера.
- Полученную публичную ссылку скрипт **проверяет тоже** (до 45 секунд) и пишет
  «Ссылка проверена: отвечает игрой (HTTP 200)». Свежий адрес туннеля первые
  секунды отдаёт «не удаётся получить доступ к сайту», пока маршрут не разошёлся
  по узлам провайдера, — проверка отсекает как раз этот момент.
- Если сервер на порту уже работает, скрипт **не поднимает второй** и не трогает
  идущую партию — просто вешает туннель на работающий сервер. При выходе такой
  сервер остаётся жить, гасится только туннель.
- Туннель, оставшийся от прошлого запуска, скрипт снимает сам на старте.
- По умолчанию используется Cloudflare (`-Provider cf`); он требует `cloudflared`,
  зато задержка ниже. `npm run play:lhr` — то же самое через localhost.run.

Дальше — разбор по частям: локальный запуск, локальная сеть и туннели по
отдельности.

## 1. Локально (на своей машине)

```bash
npm install
npm start            # http://localhost:3000  (порт меняется через PORT)
```

`localhost` доступен только на этом же компьютере — для друзей нужен один из
вариантов ниже.

## 2. Друг в той же сети (Wi-Fi/LAN)

1. Узнай свой локальный IP (адаптер вида `192.168.x.x`):

   ```powershell
   Get-NetIPAddress -AddressFamily IPv4 |
     Where-Object { $_.IPAddress -like '192.168.*' } |
     Select-Object IPAddress, InterfaceAlias
   ```

2. Открой порт `3000` в брандмауэре (один раз, **PowerShell от администратора**).
   `-Profile Any` важен, если сеть отмечена как «Общедоступная» (Public):

   ```powershell
   New-NetFirewallRule -DisplayName "Codenames 3000" -Direction Inbound `
     -Action Allow -Protocol TCP -LocalPort 3000 -Profile Any
   ```

3. Дай другу ссылку с твоим IP и кодом комнаты (4 символа из шапки «Комната»):

   ```
   http://192.168.0.135:3000/?room=КОД
   ```

Проверка: открой этот же адрес с телефона по той же Wi-Fi (мобильный интернет
выключи). Не открывается — почти всегда дело в брандмауэре (шаг 2).

## 3. Друг в другой сети (через интернет) — Cloudflare Tunnel

Локальный IP снаружи не виден; нужен туннель — он даёт временный публичный
`https://…`-адрес и пробрасывает его на твой `localhost:3000`. Открывать порты и
менять брандмауэр не нужно (соединение исходящее).

**Установка (один раз):**

```powershell
winget install --id Cloudflare.cloudflared
```

**Запуск туннеля** (в отдельном окне; `npm start` при этом работает в другом):

```powershell
cloudflared tunnel --url http://localhost:3000
```

**Через скрипт `npm run tunnel:cf`** — он сам найдёт `cloudflared`, поднимет
quick-туннель, вытащит адрес `*.trycloudflare.com` из вывода и напечатает готовую
(кликабельную в Windows Terminal / VS Code) ссылку. Скрипт поднимает **только
туннель**: сервер должен уже работать в другом окне (`npm start`). Нужно и то и
другое одной командой — `npm run play` (см. «Быстрый старт» выше).

```powershell
npm run tunnel:cf
# сразу с кодом комнаты:
npm run tunnel:cf -- -Room ABCD
# другой порт, если сервер не на 3000:
npm run tunnel:cf -- -Port 4000
```

Cloudflare обычно даёт заметно меньшую задержку, чем localhost.run (раздел 4),
поэтому это предпочтительный вариант для игры.

> Отдельная пошаговая инструкция «создать туннель и узнать его ссылку» (в т. ч.
> надёжный способ получить адрес через файл) — в
> [cloudflare-tunnel.md](cloudflare-tunnel.md).

В первых строках вывода появится рамка с адресом:

```
+--------------------------------------------------------------+
|  Your quick Tunnel has been created! Visit it at:            |
|  https://случайные-слова-1234.trycloudflare.com              |
+--------------------------------------------------------------+
```

Собери ссылку для друга: этот адрес **+** `/?room=КОД`:

```
https://случайные-слова-1234.trycloudflare.com/?room=КОД
```

Игра по `https` работает: клиент сам поднимает защищённый `wss://`
(см. `public/js/net/socket.js` — протокол берётся из `location.protocol`).

**Важно:**

- Нужны **два окна одновременно**: `npm start` и `cloudflared`. Закрыл туннель —
  ссылка умерла; запустил заново — адрес `trycloudflare` стал другим (на
  бесплатном режиме он временный).
- Ссылку другу вставлять **в адресную строку браузера**, а не в поиск.

**Быстрая альтернатива без установки** — `localhost.run` по SSH (см. раздел 4).

## 4. Друг в другой сети — localhost.run (без установки, скрипт)

Если ставить `cloudflared` не хочется: в Windows 10/11 уже есть штатный `ssh`, а
сервис `localhost.run` поднимает туннель прямо по нему и выдаёт временный
публичный `https://…lhr.life`. WebSocket (`wss`), нужный игре, поддерживается.

**Вручную одной командой** (в отдельном окне, при работающем `npm start`):

```powershell
ssh -R 80:localhost:3000 nokey@localhost.run
```

В выводе будет строка с адресом, например
`https://случайные-символы.lhr.life`. Ссылка другу — адрес `+` `/?room=КОД`.

**Через скрипт `scripts/tunnel.ps1`** — он сам поднимает туннель, вытаскивает
адрес из вывода и печатает готовую (кликабельную в Windows Terminal / VS Code)
ссылку:

```powershell
npm run tunnel
# или сразу с кодом комнаты:
npm run tunnel -- -Room ABCD
# другой порт, если сервер не на 3000:
npm run tunnel -- -Port 4000
```

Скрипт выведет:

```
  Домен туннеля: https://случайные-символы.lhr.life
  Ссылка другу:  https://случайные-символы.lhr.life/?room=КОД
  Открыть/скопировать: https://случайные-символы.lhr.life   ← кликабельно
```

Скрипт поднимает **только туннель**: сервер должен уже работать (`npm start`).
Сразу и сервер, и туннель — `npm run play:lhr`.

**Важно:**

- Окно со скриптом/`ssh` должно оставаться открытым — закрыл его, туннель умер.
  Остановить: `Ctrl+C` в этом окне (скрипт сам погасит `ssh`). Если окно закрыли
  крестиком и `ssh` остался в фоне — снять его командой `npm run tunnel:stop`
  (скрипт также снимает висящий туннель сам при следующем запуске).
- Адрес `*.lhr.life` **временный**: при перезапуске туннеля он новый — отправь
  другу обновлённую ссылку.
- Если скрипт ругается «на порту 3000 никто не слушает» — сначала подними сервер
  (`npm start`) в другом окне.
- Нет `ssh`? Поставь компонент **OpenSSH Client**: Параметры → Приложения →
  Дополнительные компоненты → Добавить → OpenSSH Client.

## 5. Постоянный хостинг на VPS (адрес не меняется)

Игру можно развернуть на своём VPS постоянно: она работает как systemd-сервис за
nginx, переживает перезагрузку сервера, и домашняя машина с туннелями больше не
нужна. Комната по-прежнему существует только пока жив процесс — перезапуск
сервиса обрывает идущие партии.

Ниже `<домен>` — домен сайта, а подпуть игры взят как `/code-names/`; конкретные
адреса стенда в репозитории не публикуются.

### Что где лежит

| Что                  | Где                                                                         |
|----------------------|-----------------------------------------------------------------------------|
| ОС                   | Ubuntu 24.04, Node.js 22 из репозитория NodeSource                          |
| Код                  | `/opt/codenames/app`, владелец — системный пользователь `codenames`         |
| Сервис               | `/etc/systemd/system/codenames.service`, слушает `127.0.0.1:3000`           |
| nginx                | `/etc/nginx/sites-available/<домен>.conf`                                   |
| Заглушка корня сайта | `/var/www/<домен>/index.html`                                               |
| Сертификат           | Let's Encrypt, `/etc/letsencrypt/live/<домен>/`, обновляет таймер `certbot` |

### Как это устроено

nginx слушает 80/443, в корне отдаёт статическую заглушку, а `/code-names/`
проксирует в приложение на `127.0.0.1:3000` — вместе с заголовками `Upgrade` и
`Connection`, без которых WebSocket игры не поднимется.

Префикс `/code-names` **срезается при проксировании** (`proxy_pass` со слэшем на
конце), поэтому серверный код продолжает считать, что живёт в корне домена, и
обработка `/admin` работает без изменений. Клиент, наоборот, обязан знать префикс
— он вычисляет его сам из URL собственного модуля (`public/js/util/basePath.js`),
так что одна и та же сборка работает и на `localhost:3000`, и под префиксом.

Порт приложения снаружи закрыт: в unit задан `HOST=127.0.0.1`, наружу отдаёт
только nginx.

### Обновить код на сервере

1. На своей машине: запушить изменения в `main` на GitHub.
2. Зайти на VPS по SSH.
3. `cd /opt/codenames/app && sudo -u codenames git pull` — подтянуть код.
4. `sudo -u codenames npm ci --omit=dev` — только если менялись зависимости.
5. `systemctl restart codenames` — перезапустить сервис.

Репозиторий склонирован по HTTPS, поэтому `git pull` работает без ключей, пока
репозиторий публичный. Если провайдер закрывает исходящий 22-й порт, клон по SSH
оттуда не поднимется — HTTPS в такой сети остаётся рабочим вариантом.

### Диагностика

| Команда                            | Что показывает                              |
|------------------------------------|---------------------------------------------|
| `systemctl status codenames`       | жив ли процесс игры, когда стартовал        |
| `journalctl -u codenames -f`       | живой лог приложения                        |
| `ss -tlnp \| grep 3000`            | слушает ли приложение и на каком интерфейсе |
| `nginx -t`                         | синтаксис конфигурации nginx                |
| `tail -f /var/log/nginx/error.log` | ошибки прокси, в т. ч. отказы WebSocket     |
| `certbot certificates`             | срок действия сертификата                   |

### Нюансы

- Адрес без завершающего слэша (`/code-names`) отдаёт 301 на `/code-names/`:
  относительные пути ассетов иначе резолвились бы от корня сайта.
- Админ-панель открывается на подпути игры: `…/code-names/admin`.
- Порты 80/443 отданы nginx. Если на том же VPS живёт xray reality, которому
  нужен 443, разводить их придётся по SNI.
- Поддомен `www` попадает в сертификат только если его A-запись указывает на этот
  же VPS на момент выпуска; иначе выпуск с `-d www.…` повторяется после правки
  DNS.
